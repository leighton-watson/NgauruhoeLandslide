# Locating a landslide at Ngauruhoe using seismic data

This repository contains the data-processing, source-localisation, and figure-generation code associated with the study:

> Watson, L. M., and Lamb, O., *Locating a landslide at Ngauruhoe (New Zealand) using seismic data*.

The study examines a suspected landslide signal recorded at Ngauruhoe, New Zealand, on 21 March 2026. It compares three approaches for estimating the source location:

1. **Amplitude source location (ASL)**, using absolute seismic amplitudes across the network.
2. **Seismic amplitude ratio analysis (SARA)**, using relative amplitudes between station pairs.
3. **Seismo-acoustic differential-arrival localisation**, using the delay between seismic and infrasound signal onsets.

The repository includes the event waveforms and station metadata used by the analyses, derived intermediate results, and scripts used to generate the manuscript figures.

## Software requirements

The analysis was developed in Python. Python 3.10 or later is recommended.

Create and activate a virtual environment:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
```

Install the required Python packages:

```bash
python -m pip install \
  numpy pandas scipy matplotlib obspy pyproj \
  geopandas shapely contextily matplotlib-scalebar openpyxl
```

The mapping scripts may download web-map tiles when run and therefore require an internet connection. The data-download and calibration scripts also access GeoNet's FDSN services.

## Data

The `DATA/` directory contains the inputs required for the main event analysis:

- sensitivity-corrected seismic and infrasound waveforms in MiniSEED format;
- station metadata in StationXML format;
- gridded topography in NumPy format;
- hourly rainfall observations; and
- station and sensor information.

The scripts `DATA/download_seismic_data.py` and `DATA/download_infrasound_data.py` show how the waveform data and response metadata were obtained from GeoNet. Run these scripts from within `DATA/` so that their outputs are written to the expected location:

```bash
cd DATA
python download_seismic_data.py
python download_infrasound_data.py
cd ..
```

The event files required by the main analyses are already included, so downloading them again is not necessary for reproducing the archived results.

## Reproducing the analyses

Run commands from the repository root unless stated otherwise.

### 1. Site-amplification correction

The site-amplification analysis uses selected regional earthquakes to estimate relative station factors:

```bash
python SiteAmplification/site_amplification.py
```

The principal table used by the landslide source-localisation analyses is:

```text
SiteAmplification/site_amplification_summary.csv
```

This analysis downloads waveform data and therefore requires an internet connection. Precomputed results are included in the repository.

### 2. Attenuation analysis

Estimate attenuation parameters from regional earthquakes:

```bash
python Attenuation/estimate_q_from_earthquakes.py
```

The resulting tables are written to `Attenuation/RESULTS/`. The diagnostic attenuation plot can be regenerated with:

```bash
python Attenuation/plot_attenuation_residual_fit.py
```

This analysis also accesses GeoNet services. Precomputed result tables are included.

### 3. Seismic and infrasound onset times

Run the offline change-point onset analysis:

```bash
python OnsetTimes/offline_change_point_arrival_picks.py
```

This writes the arrival-pick table, saved analysis variables, and diagnostic figures to `OnsetTimes/`. The archived results can also be loaded by the script without recomputing the picks; see the configuration switches near the top of the script.

### 4. ASL and SARA source localisation

Run the two amplitude-based localisation methods:

```bash
python run_ASL.py
python run_SARA.py
```

The saved result bundles are written to:

```text
Outputs/ASL_output.npz
Outputs/SARA_output.npz
```

The principal analysis settings—including stations, time windows, frequency band, search-grid spacing, attenuation, and site-amplification corrections—are defined near the top of each runner script.

To compare quality thresholds that retain equivalent fractions of the ASL and SARA time windows, run:

```bash
python run_matchQualityThresholds.py
```

### 5. Computational benchmark

Benchmark total and localisation-only runtimes as a function of station count:

```bash
python run_computational_cost.py
```

The benchmark results are saved in `Outputs/`. Runtime values depend on the computer, operating system, Python environment, and current configuration, so newly generated values need not exactly match the archived tables.

## Reproducing the figures

The archived outputs allow most manuscript figures to be regenerated without rerunning the computationally intensive analyses:

```bash
python Fig1_map.py
python Fig2_waveforms.py
python Fig3_spectra.py
python Fig4_amplification_attenuation.py
python Fig5_results_timesSeries.py
python Fig6_results_map.py
python Fig7_picks.py
python Fig8_differential_arrivals.py
python Fig9_compare_source_locations.py
python Fig10_computational_cost.py
```

Figures are written to `FIGURES/`. `Fig3_spectra.py` retrieves waveform and response information from GeoNet when run, while mapping scripts that use satellite imagery require network access to retrieve basemap tiles.

## Important path note

The code was reorganised from a larger analysis directory into this paper-specific repository. A small number of scripts still contain imports or paths beginning with `AnalysisCodes` or referring to data in the parent directory. These are legacy path assumptions and may need to be changed to the corresponding files in this repository before running the code as a completely standalone checkout. In particular, inspect:

- `asl.py`;
- `source_localisation.py`;
- `run_matchQualityThresholds.py`;
- `Fig5_results_timesSeries.py`;
- `Fig6_results_map.py`;
- `Fig8_differential_arrivals.py`; and
- `Fig9_compare_source_locations.py`.

The archived input data, derived outputs, and final figures are included so that the results remain inspectable even where an old path assumption is present.
